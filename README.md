# OrbitLens AI

*Part of the [AI_Projects](https://github.com/nekzahid123-afg/AI_Projects) collection — AI-powered automation scripts and workflows for streamlining repetitive tasks.*

**Spacecraft telemetry anomaly detection with RAG-grounded AI insights and a conversational mission support assistant — powered by IBM Granite on watsonx.ai.**

OrbitLens AI ingests satellite telemetry (CSV) plus supporting mission
documentation (CSV, TXT, PDF, Markdown), detects anomalies using
statistical and Isolation-Forest detectors, and uses a fully implemented
semantic-chunking RAG pipeline to ground IBM Granite's explanations —
both in a downloadable mission report and in a live chat window — so
every AI claim is traceable to real telemetry data or a retrieved
document chunk, never free-floating model guesswork.

- **Frontend:** React 19 + Vite + TailwindCSS + Recharts (port 5173)
- **Backend:** FastAPI + pandas + scikit-learn + ChromaDB + WeasyPrint (port 8000)
- **AI:** IBM Granite via the watsonx.ai Foundation Models API, grounded by a custom RAG pipeline (sentence-transformers embeddings + ChromaDB retrieval)

---

## Key Features

- **Multi-format upload** — telemetry via CSV, plus supporting reference/mission documents via CSV, TXT, PDF, or Markdown, all through a single upload form.
- **Two-tier anomaly detection** — fast, explainable statistical thresholds (rolling mean ± std-dev / nominal ranges) plus an Isolation Forest cross-check for joint-field anomalies. No black-box custom-trained models.
- **Semantic-chunking RAG pipeline** — every uploaded document is text-extracted, split into paragraph/section-aware chunks (~300–500 tokens, ~50 token overlap), embedded locally with `sentence-transformers/all-MiniLM-L6-v2`, and stored in ChromaDB alongside a curated knowledge base — tagged by source so retrieval can span both.
- **IBM Granite via watsonx.ai** — generates the Mission Summary, per-anomaly explanations, root-cause hypotheses, and recommendations, all grounded in retrieved chunks. Every insight shows its source snippet so a user can verify the claim.
- **Mission Support Chat** — a floating chat window for free-form, RAG-grounded follow-up questions about the current session (e.g. *"why did the battery voltage drop?"*). Answers are generated by Granite, grounded in the same knowledge base + session documents, and cite their sources. A short rolling conversation history keeps follow-ups coherent.
- **Hallucination guardrails** — low-similarity retrieval triggers an explicit "no strong reference match" response instead of a guess, in both the Insights panel and Chat. If the watsonx.ai call fails or times out, the system falls back to a template-based explanation so the demo never breaks.
- **Downloadable mission report** — combines the health score, anomaly table, AI explanations, and mission summary into a single Markdown or PDF export.

  ## A Note on Insight Generation Behavior

Not every anomaly triggers a full Granite + RAG call. To keep the demo fast
and cost-efficient, only **higher-severity anomalies** (currently:
`HIGH` severity, and select `MEDIUM` cases) are routed through the full
RAG-grounded Granite pipeline — these show a plausible root-cause
hypothesis, a concrete recommendation, and a non-zero **Sources** count.

Lower-severity anomalies (`LOW`, and most `MEDIUM`) are explained using a
**deterministic template-based fallback** built directly from the anomaly's
statistical description (rolling mean, std-dev, nominal range) — the same
fallback used if a live watsonx.ai call fails or times out. These show
`Sources (0)` and the generic phrasing *"requires further investigation via
subsystem telemetry review."*

This is intentional, not a bug: it mirrors real mission-ops triage, where
minor deviations get a standard boilerplate flag while significant/critical
anomalies get deeper, LLM-reasoned analysis. It also guarantees the app
**never crashes or stalls** even if the watsonx.ai API is rate-limited or
unavailable during a demo.

## Environment Variables

Copy `backend/.env.example` to `backend/.env` and fill in your own watsonx.ai credentials:

```env
SESSION_TTL_SECONDS=3600
WATSONX_API_KEY=your_ibm_cloud_api_key
WATSONX_PROJECT_ID=your_watsonx_project_id
WATSONX_URL=https://us-south.ml.cloud.ibm.com
GRANITE_MODEL_ID=ibm/granite-13b-instruct-v2
```

| Variable | Default | Description |
|---|---|---|
| `SESSION_TTL_SECONDS` | `3600` | How long (seconds) an uploaded session — including its documents and chat history — is kept in memory before eviction. |
| `WATSONX_API_KEY` | — | Your IBM Cloud API key, used to authenticate with watsonx.ai. **Never commit this — it stays server-side only.** |
| `WATSONX_PROJECT_ID` | — | The watsonx.ai project ID associated with your API key. |
| `WATSONX_URL` | region-dependent | The watsonx.ai regional endpoint for your account. |
| `GRANITE_MODEL_ID` | `ibm/granite-13b-instruct-v2` | Which IBM Granite model variant to call. |

> If watsonx.ai credentials are missing or a call fails, the system falls back to a template-based, purely local explanation — the app still runs end-to-end without any API key, just without live Granite-generated text.

## API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/upload` | Upload a telemetry CSV. Returns `session_id`, `health_score`, `summary_stats`, `preview_rows`. |
| `GET` | `/upload/sample` | Run the same pipeline on the bundled `sample_mission.csv`. |
| `POST` | `/documents` | Upload and ingest a CSV/TXT/PDF/Markdown reference document for a session (extract → semantically chunk → embed → store in ChromaDB). Returns `document_id`, `chunk_count`, `status`. |
| `GET` | `/telemetry?session_id=<id>` | Return all parsed telemetry rows for a session. |
| `GET` | `/anomalies?session_id=<id>` | Run anomaly detection (statistical + Isolation Forest) and return results. Cached after first call. |
| `POST` | `/insights` | Generate RAG-grounded AI insights for every detected anomaly via Granite (watsonx.ai). Body: `{"session_id":"<id>"}`. Idempotent — cached after first call. |
| `POST` | `/chat` | Send a free-form chat message for a session; runs RAG retrieval + Granite (watsonx.ai) and returns a grounded response with sources. Body: `{"session_id":"<id>", "message":"<text>"}`. |
| `GET` | `/report?session_id=<id>&format=markdown\|pdf` | Download the mission report. Falls back to Markdown if PDF libraries are unavailable. |
| `GET` | `/health` | Liveness check. Returns `{"status":"ok"}`. |

### Error shapes

All error responses share the same envelope:

```json
{
  "error": {
    "code": "SESSION_NOT_FOUND",
    "message": "Session 'abc123' not found or expired."
  }
}
```

| Code | HTTP | When |
|------|------|------|
| `SESSION_NOT_FOUND` | 404 | `session_id` does not exist or has expired |
| `MISSING_COLUMNS` | 422 | Uploaded telemetry CSV is missing required columns |
| `UNSUPPORTED_FILE_TYPE` | 422 | An uploaded reference document isn't CSV/TXT/PDF/MD, or a scanned/image-only PDF has no extractable text layer |
| `ANOMALIES_NOT_FOUND` | 400 | `POST /insights` called before `GET /anomalies` |
| `INSIGHTS_NOT_FOUND` | 404 | `GET /report` called before `POST /insights` |

## Demo Script

**Total time: ~5 minutes**

1. **(30 s) Setup** — Start both processes (`uvicorn` + `npm run dev`). Open **http://localhost:5173** in your browser.

2. **(30 s) Load sample mission** — Click **"Try Sample Mission"**. The dashboard renders with the health score badge, telemetry charts, and subsystem status table populated automatically from `backend/datasets/sample_mission.csv`.

3. **(60 s) Review anomaly markers** — Scroll through the telemetry charts. Colored dots appear on the chart lines at anomaly timestamps:
   - 🔴 **Red** = high severity (battery voltage drop to 20 V; thermal spike to 65 °C)
   - 🟡 **Amber** = medium severity (signal strength dropout)
   - Hover any dot to see the field value and detection detail in the tooltip.

4. **(90 s) Generate AI Insights** — Click **"Generate AI Insights"**. InsightCards appear for each anomaly, generated live by IBM Granite on watsonx.ai, grounded via RAG — each shows:
   - **Explanation** (what happened and when)
   - **Hypothesis** (probable root cause)
   - **Recommended Action**
   - **Sources** (expandable — shows the retrieved grounding snippet, or "no reference sources" if no strong match was found)

5. **(45 s) Ask the Mission Support Chat** — Open the chat widget and ask a live follow-up question (e.g. *"why did the battery voltage drop?"*). The response is generated by Granite, grounded in the same RAG pipeline, and shows its sources — demonstrating the conversational layer on top of the Insights pipeline.

6. **(30 s) Download Mission Report** — Click **"Download Mission Report"**. A file downloads containing the health score, anomaly table, full AI explanation sections, and Mission Summary.

## Architecture

Two independent local processes communicate over REST JSON:

```
Browser (5173)  ←→  Vite Dev Server  ←→  FastAPI (8000)  ←→  IBM Granite (watsonx.ai)
                                              ↓
                                          ChromaDB (local, persisted)
```

Session data (parsed DataFrames, anomalies, insights, ingested document chunks, chat history) is stored in-memory in the backend process and evicted after `SESSION_TTL_SECONDS`. ChromaDB is the only persistent store, holding both the curated knowledge base and per-session ingested documents, tagged by source.

```
backend/
  main.py                     ← FastAPI app, CORS, route registration
  sessions.py                 ← in-memory session store with TTL eviction
  api/
    routes_upload.py          ← POST /upload, GET /upload/sample
    routes_documents.py       ← POST /documents (ingest reference docs)
    routes_telemetry.py       ← GET /telemetry
    routes_anomalies.py       ← GET /anomalies (statistical + IF + dedup)
    routes_insights.py        ← POST /insights (idempotent, RAG + Granite)
    routes_chat.py            ← POST /chat (RAG + Granite, session-scoped)
    routes_report.py          ← GET /report (markdown + optional PDF)
  anomaly/
    models.py                 ← Canonical Anomaly schema
    nominal_ranges.py         ← Single source of truth for field ranges
    statistical.py            ← Z-score + nominal-range detector
    isolation_forest.py       ← sklearn IsolationForest detector
  ai/ (rag)
    chunker.py                ← Semantic, paragraph/section-aware chunking
    embedder.py                ← sentence-transformers/all-MiniLM-L6-v2
    rag_retriever.py           ← Top-k cosine-similarity retrieval over ChromaDB
    prompt_builder.py          ← Assembles anomaly/chat context + retrieved chunks
    granite_client.py          ← IBM Granite via watsonx.ai
  knowledge_base/
    document_extractor.py      ← Multi-format text extraction (CSV/TXT/PDF/MD)
    raw_docs/                  ← Curated reference documents
    chroma_store/               ← Persisted ChromaDB vector store
  insights/
    generator.py               ← Insight generation orchestration
  report/
    report_generator.py        ← Markdown + optional WeasyPrint PDF generator
  datasets/
    sample_mission.csv         ← 500-row telemetry with 3 injected anomaly windows
    sample_mission_2.csv       ← Alternative dataset for E2E validation
    ground_truth_anomalies.json ← Injected window definitions for unit tests

frontend/
  src/
    components/
      UploadPanel/            ← CSV/TXT/PDF/MD upload + "Try Sample Mission" button
      Dashboard/              ← TelemetryChart (Recharts), HealthScore badge
      AIInsightsPanel/        ← InsightCard list + Sources accordion
      MissionReport/          ← Download button
      ChatSupport.jsx         ← Mission Support Chat widget
    api/
      client.js, telemetry.js, insights.js, report.js, documents.js, chat.js
```

## Why RAG Instead of Prompting Alone

Without RAG, Granite would be guessing at spacecraft subsystem behavior from general training knowledge — plausible-sounding but ungrounded, and impossible to verify. RAG lets every claim point at the exact source sentence behind it — in the report and in live chat — which is the core "translate complex data into clear insights you can trust" pitch of this project.

**How hallucination is limited:**
- Low-similarity retrieval triggers an explicit "no strong reference match" response instead of a guess.
- The prompt explicitly instructs Granite to admit uncertainty rather than extrapolate.
- The UI always shows the raw anomaly data next to the AI-generated text, in both Insights and Chat.

## Known Limitations

- Uses simulated telemetry data, not a live satellite feed.
- The curated knowledge base is intentionally small for a hackathon build — RAG value is real but modest in scale, even with user-uploaded documents added per session.
- PDF ingestion only supports embedded-text PDFs; scanned/image-only PDFs are not yet OCR'd.
- No authentication/user accounts — sessions are anonymous and in-memory only.
